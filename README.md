# 짤깍 · JJALKKAK

한국어로 GIF를 검색하고, 대화에 답장할 GIF를 추천받는 데스크톱 검색창입니다.

```bash
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173/ 을 열면 샘플 GIF로 화면을 확인할 수 있습니다. 브라우저에서 GIF를 클릭하면 클립보드에 복사합니다.

데스크톱은 Vite를 실행한 상태에서 다른 터미널에 `npm run desktop`을 실행합니다. macOS에서 파일 클립보드를 사용하려면 Swift 컴파일러가 필요합니다. 앱을 처음 시작하면 패널이 열리고, 이후에는 맥 `⌥ Space` 또는 Windows `Alt+Space`로 다시 엽니다. GIF를 클릭하거나 방향키로 선택 후 Enter를 누르면 파일이 복사되고 패널이 닫힙니다. 카카오톡에서 `⌘V` 또는 `Ctrl+V`로 붙여넣습니다. 카드에서 파일을 끌어다 놓을 수도 있습니다.

## Vercel 배포

저장소 루트에서 Vite로 빌드합니다. 빌드 명령은 `npm run build`, 출력 폴더는 `dist`입니다.
배포 화면 하단의 `KLIPY 설정`을 열고 KLIPY 웹 클라이언트용 앱 키를 입력합니다.
키는 같은 탭의 세션 저장소에만 저장하며 KLIPY 요청에만 사용합니다. 샘플로 전환하면 지워집니다.

브라우저에서 보이는 단축키 안내는 데스크톱 앱을 위한 것입니다. 웹에서는 브라우저가 원본 GIF 클립보드를 지원하면 바로 복사합니다. macOS에서 지원하지 않는 브라우저는 짤깍 앱을 통해 원본 GIF 파일을 복사합니다. 앱 ZIP은 `bash scripts/package-mac.sh`로 빌드합니다.
문자 추천은 기본적으로 기기 내 키워드 규칙을 사용하며, 실시간 모드에서는 해당 검색어로 KLIPY 결과를 조회합니다.

## 실시간 검색과 로컬 AI

- 샘플 모드에서 검색과 추천을 바로 시연할 수 있습니다.
- KLIPY 실시간 검색은 `.env.example`을 `.env.local`로 복사하고 `VITE_GIF_MODE=live` 및 발급받은 `VITE_KLIPY_KEY`를 설정한 뒤 로컬 Electron과 Vite를 다시 시작합니다.
- Electron에서 로컬 Ollama를 실행하고 설치한 모델 이름을 `VITE_OLLAMA_MODEL`에 지정하면 메시지의 감정과 맥락을 분석해 영어 검색어를 만듭니다. KLIPY에는 이 검색어가 전달됩니다. 기본 모드의 대화 추천은 기기 내 키워드 규칙을 사용합니다.
- `npm run build`로 타입 검사와 웹 빌드를 실행합니다.

## 카카오톡 GIF 복사 방식 비교

macOS에서 같은 GIF를 원본 바이트와 파일 객체로 각각 복사해 붙여넣기 결과를 비교합니다.

```bash
bash run-gif-test.sh
```

Swift 컴파일러가 필요합니다. 터미널에서 설치 안내가 나오면 `xcode-select --install`을 실행한 뒤 다시 시작하세요.

1. **A. 원본 GIF 복사**를 누르고 맥 카카오톡 테스트 채팅방에서 `⌘V`로 붙여넣습니다.
2. 붙여넣어진 형태를 확인하고 전송합니다. 받는 사람 화면에서 숫자 **1 → 2 → 3**이 반복되는지 확인합니다.
3. **B. GIF 파일 복사**로 같은 절차를 반복합니다. 파일로 보내졌다면 채팅 화면과 파일을 열었을 때의 재생 여부를 구분해서 기록합니다.

| 복사 방식 | 붙여넣기 결과 (이미지 / 파일 / 변화 없음) | 수신 화면에서 재생 | 파일을 열면 재생 |
| --- | --- | --- | --- |
| A. 원본 GIF 바이트 | | | |
| B. `.gif` 파일 객체 | | | |

B는 저장소 안의 `fixtures/123.gif`를 참조합니다. 붙여넣는 동안 해당 파일이 있어야 합니다. `bash run-gif-test.sh --check`는 별도 클립보드를 사용해 두 복사 형식과 GIF 프레임 수를 확인합니다.


## 웹에서 클릭 후 카카오톡에 붙여넣기 (macOS)

1. 이전 짤깍 앱은 메뉴 막대에서 종료합니다.
2. https://huddling-3team.vercel.app/Jjalkkak-macOS.zip 을 받아 압축을 풀고 새 `Gifkey.app`을 한 번 실행합니다 (macOS 13 이상).
3. 앱은 창 없이 메뉴 막대에 유지됩니다. 웹에서 GIF를 클릭하고 브라우저의 로컬 네트워크 권한 요청을 허용합니다.
4. 웹에 복사 완료가 표시되면 카카오톡에서 `⌘V`로 붙여넣습니다. 전송은 사용자가 직접 합니다.
5. 앱 종료나 Mac 재시작 후에는 앱을 다시 실행합니다. 자동 시작은 등록하지 않습니다.

웹은 원본 GIF 바이트를 받아 `127.0.0.1:47653`의 맥 앱으로 전송합니다. 앱은 GIF를 검증하고 임시 `.gif` 파일을 클립보드에 기록한 뒤 성공 응답을 보냅니다. PNG 변환, 링크/텍스트 복사, 클립보드 감시는 하지 않습니다. KLIPY 키는 이 연결 앱이나 브라우저에 전달하지 않습니다. 웹 검색은 Vercel 서버를 통해 처리합니다. 앱 연결 실패는 설치/실행 안내로 표시합니다.

연결 앱은 루프백 주소에만 바인딩하고 배포 사이트의 Origin, 실행마다 바뀌는 세션 토큰, MIME 및 GIF 헤더/프레임, 24MB 크기 제한을 검사합니다. 파일은 macOS 임시 폴더에 유지되므로 붙여넣기 전에 앱이 파일을 지우지 않습니다. 카카오톡의 수신 화면에서 애니메이션이 어떻게 표시되는지는 별도 실기기 확인이 필요합니다.

검증: `npm run build`, `bash scripts/package-mac.sh`, `python3 tests/web-copy-bridge.py`.
마지막 명령은 실행 중인 연결 앱을 종료한 뒤 사용하며, 시스템 클립보드에 테스트 GIF를 복사합니다. 실제 HTTP와 macOS 클립보드의 원본 바이트, 다중 프레임 유지, 잘못된 Origin/토큰/파일/크기 차단과 실패 시 기존 클립보드 유지 여부를 검증합니다.


## 팀 공용 검색 · 서버 비밀키

웹 방문자는 API 키를 입력하지 않습니다. 브라우저는 `GET /api/gifs?q=검색어&customer_id=익명UUID`만 호출하고, Vercel 함수가 `KLIPY_API_KEY`를 사용해 KLIPY의 검색/트렌딩 결과를 가져옵니다. 빈 검색어는 트렌딩, 검색어는 최대 100자, 반환은 최대 12개입니다. 키 입력 UI를 제거하고 이전 버전에서 저장한 탭 키도 삭제합니다.

`KLIPY_API_KEY`는 Vercel Production의 Secret 환경변수로 설정합니다. `VITE_` 접두사를 사용하지 않으며 실제 값을 소스, `.env.example`, 공개 JS, ZIP, 응답 또는 로그에 쓰지 않습니다. 키가 없으면 503, 검색 제공자 연결 실패는 502, 요청 한도는 429로 표시하고 샘플 결과로 가장하지 않습니다. 서버는 필요한 GIF 필드만 반환하고 외부 오류 본문/헤더를 전달하지 않습니다.

KLIPY의 서버 호출/프록시 통합은 사전 승인이 필요하며 이 프로젝트는 사용자가 승인받았음을 확인한 뒤 서버 방식을 적용했습니다. GIF 미디어는 기존처럼 KLIPY CDN에서 직접 가져옵니다. 맥 연결 앱의 오프라인 패널은 샘플 모드를 유지합니다. 로컬 Electron 실시간 모드도 `KLIPY_API_KEY`를 메인 프로세스에서만 읽습니다.

검증: `node --test tests/klipy-search.test.mjs`는 검색/트렌딩, 실제 빈 결과, 키 누락, API 인증 오류·한도·타임아웃, 입력 검증, URL 허용 범위 및 비밀값 미노출을 검사합니다.
